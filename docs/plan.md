# 구글 시트 등록용 진행 계획 (과제 2 · 신규 프로젝트)

주제: 회의 결정 원장 Agent — 회의 전사문에서 결정·할 일을 근거 발언과 함께 추출하고, 프로젝트 기준·과거 결정·사내 정책과의 충돌을 감지해 승인된 결정만 원장에 기록. 이후 결정의 근거를 원문 발언까지 추적해 답변.

| 순번 | 영역 | 무엇을 하나 | 추가 설명 |
|---|---|---|---|
| 1 | 주제·배경 | STT 회의 전사문 기반 결정 원장 Agent | 실제 강의 녹음 교정 경험(용어 오인식·환각)에서 출발, 사내 회의의 "결정이 기록되지 않고 뒤집혀도 모르는" 문제로 확장 |
| 2 | RAG | 목적별 4개 컬렉션 분리 | R1 회의 원문(증거), R2 프로젝트 기준 문서(현재 상태, 버전), R3 결정 원장(변경 이력, 승인 후 추가), R4 사내 정책·결정 권한표(최상위, 버전 관리) |
| 3 | RAG | 우선순위·해석 규칙 | R4 > R3(유효 결정) > R2(현재 버전) > R1(근거 전용). 대체된 결정·옛 문서 버전은 검색 제외로 옛 결과 간섭 차단 |
| 4 | 기능 | 결정·할 일 추출 (근거 필수) | 결정·할 일마다 회의·화자·시각·인용 첨부, 할 일은 담당자·기한 필수 |
| 5 | 기능 | 충돌 감지 | 회의 결정과 추가 의견 모두 대상. 과거 결정 모순, 기준 문서 위반, 정책 위반, 결정 권한 밖 결정 |
| 6 | 기능 | 근거 질의 | "왜 그렇게 정했나" → 결정 원장 → 원문 발언까지 추적, 미결정이면 논의만 있었음을 안내 |
| 7 | 거버넌스 | 정책 예외 관리 | 사람이 승인한 일시 예외는 정책을 바꾸지 않고 만료일 있는 예외 기록으로 분리 |
| 8 | MCP | 도구 서버 | Tool: 회의·결정 검색, 예외 확인, 결정 제안·승인 / Resource: 정책·기준 문서 / Prompt: 추출·충돌 검토 절차 |
| 9 | 그래프 | 베이스 파이프라인 재구성 | route(회의·의견·질의) → plan → gate → research(병렬) → extract → conflict_check → validate → finalize |
| 10 | 검증 | 2단 검증 | 코드: 인용이 원문에 실제 존재하는지 / LLM 심판: 인용이 결정을 뒷받침하는지 |
| 11 | 평가 | Before/After | 정답셋 기반 추출 정확도·근거 인용 정확도·충돌 탐지율·헛경보. RAG 없음 → 원장 → 원장+기준+정책 단계별 비교 (LangSmith Dataset) |
| 12 | 운영·품질 | 로컬 모델, 모듈화, 테스트 | 기밀 회의록을 외부로 보내지 않는 Ollama 구성, 노드 모듈 분리, pytest |
