## 시연 준비

로컬 모델로 회의 정리를 기다리면 1분이 넘어서, 대화방에는 미리 실제로 돌린 답을 넣어 둔다.

1. `bash scripts/reset_demo.sh` — 원장·색인·회의 기록 초기화, 회의 5개 실제 정리(6~7분), 시드(OPS-0011 승인 대기)
2. `bash sh/run.sh` — 서버 켜기
3. `.venv/bin/python scripts/capture_demo.py` — 대화방 질문 7개를 지금 코드로 실제로 물어 `scripts/demo_outputs.json`에 저장 (4분 안팎, 저장본은 689a7d3 코드 기준으로 커밋돼 있어 코드가 바뀌었을 때만 다시)
4. `.venv/bin/python scripts/seed_demo.py` — 대화방을 받은 답으로 다시 채움
5. 리허설에서 OPS-0011을 승인했다면 발표 전에 1·4를 다시 실행 (답은 저장해 둔 것을 쓰므로 3은 다시 안 해도 됨)
6. 정한결(kjh)로 로그인한 채로 둔다. 승인 화면 바로가기: `?user=kjh&page=admin&sel=OPS-0011`

## 1. 표지 (0:00–0:10)

회의 요약 · 결정 정리 비서입니다. 회의에서 **정한 것**을 근거와 함께 남기고 지키는 에이전트입니다.

## 2. 문제 (0:10–0:35)

회의에서 정한 게 남지 않고, 뒤집혀도 모릅니다. PM이 빠진 회의에서 정해 둔 SSE를 WebSocket으로 바꾸고, PL 혼자 본부장 승인 사항인 2주 연기를 정하고, 옛 정책 문서를 근거로 MySQL을 고릅니다.
LLM만 쓰면 사내 규칙을 몰라 못 잡고, 흔한 RAG는 이미 바뀐 옛 결정을 근거로 엉뚱한 충돌을 냅니다.

## 3. 파이프라인 (0:35–1:25)

원칙은 하나입니다. **모델은 고르기만 하고, 판정과 기록은 코드와 사람이 합니다.** 검사는 네 곳입니다.
첫째, 모델은 결정이 된 발언의 번호만 고르고, 인용문은 코드가 원문에서 복사합니다. 인용을 지어낼 수 없습니다.
둘째, 모델에게는 기준과 같은지 다른지만 묻고, 그게 정책 충돌인지 권한 위반인지는 코드 판정표가 정합니다.
셋째, 틀리면 피해가 큰 판단은 계열이 다른 작은 모델 두 개가 질문을 뒤집어 가며 다시 봅니다. 네 표 중 이의가 두 표 이상이면 사람에게 넘깁니다. 이건 켜서 쓰는 옵션이고 효과는 아직 재지 못했습니다.
넷째, 답에 나온 결정 번호와 숫자를 근거와 글자로 대조합니다.
그리고 원장에 확정하는 건 팀장 승인뿐입니다.

## 4. 찾기 (1:25–2:00)

사내 규정과 기준 문서는 RAG로 찾습니다. 결정과 미결은 다르게 찾습니다. 질문의 표현을 별칭 표로 주제에 잇고, 몇 건으로 좁힌 뒤 모델이 번호만 고릅니다.
오른쪽이 이유입니다. 목록을 통째로 읽히면 400건에서 23%까지 떨어지지만, 좁힌 뒤 읽기는 92%를 유지합니다.
목록에 없는 새 주제는 모델이 이름을 짓지 않고, 팀장이 정합니다.

## 5. Before / After · 신뢰도 (2:00–2:40)

처음에는 회의 3개 작은 정답지로 쟀습니다. LLM 단독은 충돌을 못 잡고, 단순 RAG는 옛 결정으로 오탐이 나고, 이 에이전트는 100%였습니다.
그런데 이 100%는 규칙을 그 3건에 맞춘 결과였습니다. 그래서 처음 보는 회의 20개, 질문 100개로 딱 한 번 다시 쟀습니다. 자동 처리 정확도는 47.5%, 절반입니다.
그래서 원장에 자동으로 쓰지 않고, 모든 결정은 팀장 승인을 거치는 초안으로 설계했습니다. 대신 사람에게 넘긴 것의 79%는 실제로 애매하거나 틀린 건이라, 넘김 판단은 쓸 만합니다.

## 6. 한계 (2:40–3:00)

dev에서 찾은 약점을 고쳐 dev 점수는 올랐지만, 시험 셋에서는 기준선 수준으로 돌아왔습니다. 다음은 주제 정확도, 권한 기준값 비교, 추출 안정화입니다. 기밀이라 외부 LLM을 쓰지 않아 회의 정리는 중앙값 174초로 느립니다. 화면으로 보겠습니다.

## 7. 시연 (3:00–5:00)

(대화방의 기존 대화는 미리 실제로 돌린 결과라는 점을 먼저 말한다)

1. **OPS-M04 회의 정리** (3:00–3:30) — 결정 4건 중 3건이 확인 필요입니다. 2주 연기는 권한표 기준과 숫자로 비교해서 본부장 승인이 필요하다고 알려 줍니다. 문제없는 런북 캐시 1건만 승인 대기로 올라갑니다.
2. **승인함 → 수정 창** (3:30–4:10) — 팀장 화면입니다. OPS-0011을 열면 근거 발언이 앞뒤 원문과 함께 보입니다. 주제를 실시간 전송으로 잘못 바꾸면 기존 결정 OPS-0007이 대체된다는 경고가 바로 뜹니다. 취소하고 승인합니다.
3. **이어 묻기** (4:10–4:35) — 'Redis 캐시 쓰기로 했어?' 방입니다. 별칭으로 캐시 주제에 닿아, Redis 캐시를 기각하고 런북 문서만 캐시하기로 한 OPS-0011을 근거로 답합니다. 여기서 "이거 누가 승인했어?"를 입력하면, 이런 사실 질문은 모델 없이 표에서 바로 답하고 방금 승인한 사람이 나옵니다.

## 예상 질문

- **Multi-Agent가 맞나?** → 감독자가 하위 에이전트를 부르는 구조는 아닙니다. 역할을 나눈 구조입니다: 8b가 추출·판정, 계열이 다른 작은 모델 둘이 위험한 판단만 검토, 확정은 사람. 그래프 안에서는 계획·조사·분석·검증을 노드로 나눴습니다.
- **교차검증이 의미가 있나? 온도 0인데?** → 온도 0이면 같은 모델에 다시 물어도 같은 답이라 의미가 없습니다. 그래서 다른 계열 모델 두 개에, 질문을 정방향과 뒤집은 방향으로 물어 4표를 받습니다. 작은 모델의 무조건 yes 버릇은 뒤집은 질문이 걸러 줍니다. 이의가 결과를 자동으로 뒤집지는 않고 사람에게 넘깁니다. 다만 켜서 쓰는 옵션이고(CROSSCHECK=1), 이번 신뢰도 측정은 끈 상태로 해서 효과는 아직 재지 못했습니다.
- **왜 외부 API를 안 썼나?** → 회의 원문은 이름을 가려도 무엇을 정했는지(기술·예산·일정·고객사)가 기밀입니다. 마스킹으로 안전해지지 않습니다. 대신 로컬 8b의 한계를 좁힌 뒤 읽기로 넘었고, 외부 API는 실제 데이터가 없는 평가 도구에만 쓸 수 있습니다.
- **100%가 너무 높은데?** → 작은 정답지(회의 3)의 100%는 규칙을 그 3건에 맞춘 결과였습니다. 처음 보는 시험 셋(회의 20·질문 100, 1회)에서는 자동 처리 정확도 47.5%(95% 구간 39.4–55.7), 결정 재현율 77%, 정밀도 54.6%입니다. 그래서 원장에는 사람 승인만 기록합니다.
- **절반이면 쓸 수 있나?** → 자동으로 확정하는 도구가 아니라 초안 작성기입니다. 사람에게 넘긴 48.7% 중 78.8%가 실제로 애매하거나 틀린 건이라, 팀장이 볼 곳을 좁혀 주는 데 쓸 만합니다. 회의 처리 오류 1건도 조용히 0건으로 내지 않고 오류로 드러냈습니다.
- **고쳤는데 왜 안 올랐나?** → dev 오류를 분석해 결정·기한 규칙을 고쳤고 dev에서는 정확도 48.8→53.8%, 재현율 78→85%였지만 시험 셋은 기준선 수준입니다. 구간이 겹쳐 일반화됐다고 말할 수 없습니다. 시험 셋을 보고 다시 고치지는 않았습니다.
- **결정을 왜 RAG로 안 찾나?** → 의미가 비슷하다는 이유로 엉뚱한 결정이 붙습니다. 예: "Redis 캐시 쓰기로 했어?"가 Redis를 기각한 세션 저장소 결정에 붙습니다. 별칭 색인은 어떤 표현이 걸렸는지 남아서 설명할 수 있고, 목록이 커져도 정답률이 유지됩니다.
- **새 주제가 나오면?** → 모델은 '새 주제'라고만 표시하고 이름은 팀장이 승인 화면에서 정합니다. 모델이 이름을 지으면 같은 사안이 매번 다른 이름으로 갈라져 '같은 주제의 새 결정이 옛 결정을 대체한다'는 규칙이 깨집니다. 주제 없는 결정은 승인 버튼이 막힙니다.
- **같은 뜻의 다른 질문은?** → 찾기는 별칭으로 같은 주제에 닿아 답은 대개 같고, 저장된 답 재사용만 글자가 같을 때로 한정했습니다. 뜻이 반대인 질문에 잘못된 답을 줄 위험이 시간 절약보다 커서입니다.
- **승인을 LangGraph interrupt로 안 한 이유?** → 승인은 몇 시간에서 며칠 뒤에 일어납니다. 그래프를 멈춰 두면 대기 상태가 체크포인터에 묶이고, 서버를 다시 켜면 사라집니다. 승인 대기를 원장 상태로 두면 재시작해도 남습니다 (ADR-07).
- **LLM이 지어내면?** → 인용은 코드가 원문에서 복사하고, 원문에 없는 담당자·기한·숫자는 지우거나 다시 쓰게 하고, 세 번 실패하면 원장 기록으로 답합니다. 원장에는 사람이 승인한 것만 들어갑니다.
